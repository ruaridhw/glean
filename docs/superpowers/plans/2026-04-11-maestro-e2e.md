# Maestro E2E & CI Pipeline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace Detox with Maestro for E2E testing and add an Android E2E job to the GitHub Actions PR pipeline.

**Architecture:** Delete all Detox files and config. Write 6 Maestro YAML flow files + 2 helper sub-flows in `mobile/e2e/`. Add a new `e2e` job to `.github/workflows/mobile-ci.yml` that builds a debug APK via `expo prebuild` + Gradle, boots an Android emulator with caching, and runs `maestro test`.

**Tech Stack:** Maestro CLI (YAML flows), GitHub Actions, `reactivecircus/android-emulator-runner@v2`, `gradle/actions/setup-gradle@v4`, Expo prebuild, Android API 35

- [ ] **Step 1: Create scan-progress.yaml**

name: "Scan Progress: scan screen loads"
---

- runFlow:
    file: helpers/navigate-tab.yaml

- tapOn:
    id: "pantry.fab"
- tapOn: "Scan Receipt"

# Grant camera permission if prompted (Android system dialog)
- runFlow:

We need a small helper for the permission dialog. Create `mobile/e2e/helpers/grant-camera-permission.yaml`:

```yaml

```

Note: Maestro's `when` conditional runs the sub-flow only if the element is visible. If permission was already granted, this step is skipped. This is cleaner than the try/catch pattern in Detox.

After granting permission, the camera screen renders. Since the scan screen is a camera view and there's no reliable testID to assert on (the Detox test just checked `android.view.View`), this flow's value is verifying the navigation path works without crashing.

### Task 8: Write error-states.yaml

**Files:**
- Create: `mobile/e2e/error-states.yaml`

Ported from `e2e/error-states.test.ts`. This is the most fragile flow — it toggles airplane mode via `adb` shell commands through Maestro's `runScript`. If this proves unreliable in CI, it can be removed without affecting other flows.

- [ ] **Step 1: Create error-states.yaml**

Create `mobile/e2e/error-states.yaml`:

```yaml
appId: com.ruaridhw.glean
name: "Error States: offline banner and API error handling"
---
- runFlow: helpers/launch.yaml

# --- Test 1: Offline banner ---
# Enable airplane mode
- runScript:
    script: |
      const proc = java.lang.Runtime.getRuntime().exec(
        ["adb", "shell", "cmd", "connectivity", "airplane-mode", "enable"]
      )
      proc.waitFor()

# Wait for offline banner to appear
- extendedWaitUntil:
    visible:
      id: "offlineBanner"
    timeout: 10000
- assertVisible: "You're offline. Some features need internet."

# Disable airplane mode
- runScript:
    script: |
      const proc = java.lang.Runtime.getRuntime().exec(
        ["adb", "shell", "cmd", "connectivity", "airplane-mode", "disable"]
      )
      proc.waitFor()

# Wait for offline banner to disappear
- extendedWaitUntil:
    notVisible:
      id: "offlineBanner"
    timeout: 10000

# --- Test 2: Search error state ---
- runFlow:
    file: helpers/navigate-tab.yaml
    env:
      tab: meals
- tapOn: "Discover"
- tapOn: "Search recipes →"

# Disconnect
- runScript:
    script: |
      const proc = java.lang.Runtime.getRuntime().exec(
        ["adb", "shell", "cmd", "connectivity", "airplane-mode", "enable"]
      )
      proc.waitFor()

# Type search query and submit
- tapOn:
    id: "search.input"
    optional: true
- inputText: "chicken"
- pressKey: Enter

# Wait for error state
- extendedWaitUntil:
    visible:
      id: "search.error"
    timeout: 10000
- assertVisible: "Try again"

# Restore connectivity (cleanup)
- runScript:
    script: |
      const proc = java.lang.Runtime.getRuntime().exec(
        ["adb", "shell", "cmd", "connectivity", "airplane-mode", "disable"]
      )
      proc.waitFor()
```

Note: The search input uses `tapOn` with `optional: true` as a fallback — the search screen may auto-focus the input. If there's no testID on the search input, Maestro will find the focused text field automatically when `inputText` is called. The `id: "search.input"` is a best-guess — if this field doesn't have a testID, remove the `tapOn` step and rely on auto-focus.

```bash

```

Expected: flow passes — offline banner shows/hides, search error state appears. This flow is expected to be the least reliable due to adb network toggling. If it fails intermittently, it's acceptable to skip it in CI and run manually.

### Task 9: Add E2E job to GitHub Actions

**Files:**
- Modify: `.github/workflows/mobile-ci.yml`

- [ ] **Step 1: Add the e2e job to mobile-ci.yml**

Add the following `e2e` job after the existing `test` job in `.github/workflows/mobile-ci.yml`:

```yaml
  e2e:
    name: E2E
    runs-on: ubuntu-latest
    defaults:
      run:
        working-directory: mobile
    env:
      API_LEVEL: 35
      ARCH: x86_64
    steps:
      - uses: actions/checkout@v4

      - name: Enable KVM
        run: |
          echo 'KERNEL=="kvm", GROUP="kvm", MODE="0666", OPTIONS+="static_node=kvm"' | sudo tee /etc/udev/rules.d/99-kvm4all.rules
          sudo udevadm control --reload-rules
          sudo udevadm trigger --name-match=kvm

      - uses: actions/setup-node@v4
        with:
          node-version: '22'
          cache: 'npm'
          cache-dependency-path: mobile/package-lock.json

      - name: Install dependencies
        run: npm ci

      - uses: actions/setup-java@v4
        with:
          cache: gradle
          distribution: temurin
          java-version: 17

      - name: Gradle cache
        uses: gradle/actions/setup-gradle@v4

      - name: AVD cache
        uses: actions/cache@v4
        id: avd-cache
        with:
          path: |
            ~/.android/avd/*
            ~/.android/adb*
          key: avd-${{ env.API_LEVEL }}

      - name: Create AVD and generate snapshot for caching
        if: steps.avd-cache.outputs.cache-hit != 'true'
        uses: reactivecircus/android-emulator-runner@v2
        with:
          api-level: ${{ env.API_LEVEL }}
          arch: ${{ env.ARCH }}
          profile: pixel_7
          disable-animations: false
          emulator-options: -no-window -gpu swiftshader_indirect -noaudio -no-boot-anim -camera-back none
          force-avd-creation: false
          script: echo 'Generated AVD snapshot for caching.'

      - name: Expo prebuild
        run: npx expo prebuild --platform android --no-install

      - name: Build debug APK
        run: cd android && ./gradlew assembleDebug

      - name: Install Maestro CLI
        run: |
          curl -fsSL "https://get.maestro.mobile.dev" | bash
          echo "$HOME/.maestro/bin" >> $GITHUB_PATH

      - name: Run E2E tests
        uses: reactivecircus/android-emulator-runner@v2
        with:
          api-level: ${{ env.API_LEVEL }}
          arch: ${{ env.ARCH }}
          profile: pixel_7
          disable-animations: true
          emulator-options: -no-snapshot-save -no-window -gpu swiftshader_indirect -noaudio -no-boot-anim -camera-back none
          force-avd-creation: false
          script: |
            adb install android/app/build/outputs/apk/debug/app-debug.apk
            maestro test e2e/

      - name: Upload Maestro artifacts
        if: failure()
        uses: actions/upload-artifact@v4
        with:
          name: maestro-artifacts
          path: |
            ~/.maestro/tests/**/*.png
            ~/.maestro/tests/**/*.log
          retention-days: 14
```

Note: The `profile: pixel_7` is a CI emulator profile (hardware skin) — it doesn't need to match the local `Pixel_10_Pro` AVD. The `reactivecircus` action supports standard Android SDK profiles. The API level (35) is what matters for compatibility.
